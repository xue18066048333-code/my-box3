# 海外安保预约平台开发实施计划总览

依据：[海外安保预约平台产品需求规格书-v1.md](./海外安保预约平台产品需求规格书-v1.md)

项目拆为四个可独立验收的阶段。每一阶段完成后都有可运行的软件，不需要等全部阶段结束才看到结果。

| 顺序 | 计划 | 独立交付结果 |
|---|---|---|
| 1 | [01-服务展示与报价预约](./01-服务展示与报价预约-实施计划.md) | 客户可浏览服务、调整套餐、得到预估价并提交预约 |
| 2 | [02-订单查询与免注册验证](./02-订单查询与免注册验证-实施计划.md) | 客户通过安全验证查看自己的订单，不依赖注册账号 |
| 3 | [03-后台资金方案与运营](./03-后台资金方案与运营-实施计划.md) | 两国负责人可核款、发方案、处理退款和安排服务 |
| 4 | [04-多语言安全与上线](./04-多语言安全与上线-实施计划.md) | 四语内容管理、安全加固、移动端验收及上线准备完成 |

推荐技术方案：Next.js 16 App Router、TypeScript、Node.js 24 LTS、Supabase PostgreSQL/Auth/Storage、Zod、Vitest、Testing Library、Playwright。采用一个全栈代码库，客户网页与管理后台共享数据模型和业务规则，减少小团队维护成本。

选择依据：Node.js 24当前处于LTS；Next.js 16支持App Router并要求Node.js 20.9以上；Supabase提供PostgreSQL、后台身份认证、行级权限和私有文件存储，适合两国权限隔离及付款凭证访问控制。

开发时必须先建立测试环境，不能把演示价格、银行账户或测试凭证带入正式环境。所有上线参数从后台或环境配置读取。

每阶段完成后需由业务方在测试环境验收。阶段1最适合作为第一笔开发投入，因为它最早验证客户是否能看懂产品并愿意提交预约。
