# 海外安保预约平台产品需求规格书 v1.0

日期：2026-10-13  
状态：待用户书面确认  
产品暂定名：境安 / Borderless Security

## 1. 项目目标

建设一个面向海外中国企业、华人、商务人士和游客的安保服务预约平台。第一阶段提供适合手机访问的网页，客户无需安装APP即可浏览、测算和预约；业务验证后再开发安卓和iOS应用。

产品要解决三个问题：客户看不懂安保方案、复杂服务难以形成透明的预约流程、运营方修改产品和价格过度依赖技术人员。

第一阶段成功标准：

1. 客户能在手机上找到适合的服务场景，理解套餐包含内容和价格构成。
2. 客户无需注册即可提交需求、支付订金凭证、确认最终方案并查看订单状态。
3. 坦桑尼亚和泰国负责人能独立处理本国订单，总管理员能管理全部业务。
4. 运营人员能在后台修改产品、四语内容、价格、地区、收款和业务规则，无需改代码。
5. 所有报价、收款、退款和方案确认均保留操作及版本记录。

## 2. 第一阶段范围

### 2.1 包含

- 客户手机网页。
- 运营管理后台。
- 中文、英文、泰文、斯瓦希里文框架。
- 坦桑尼亚全国预约，以达累斯萨拉姆及周边为重点区域。
- 泰国全国预约，以后台设置的基准城市计算基础价格，其他地区人工确认附加费。
- 服务展示、套餐配置、费用预估、免注册预约、人工转账凭证、人工核款、最终方案确认、尾款或月度付款记录、订单进度、退款记录。
- 两国负责人和总管理员权限。
- 标准短期服务、驻场服务和定制服务三类报价模型。

### 2.2 不包含

- 安卓和iOS原生应用。
- 在线银行卡或电子钱包自动扣款。
- 客户自主挑选具体安保人员。
- 人员考勤、工资核算和完整人力资源系统。
- 自动生成法律合同或替代当地法律、税务及资质审查。
- 实时聊天、即时定位、轨迹追踪、报警调度中心。
- 自动决定武装服务是否可承接。

以上功能可在后续版本评估，不阻塞第一阶段上线。

## 3. 服务目录与下单类型

| 服务 | 下单类型 | 默认计价单位 | 关键可选项 |
|---|---|---|---|
| 接送机安保 | 标准套餐 | 人/次或人日 | 人数、时长、车辆、非武装/武装申请 |
| 商务随行 | 标准套餐 | 人日 | 人数、天数、每日时长、车辆、非武装/武装申请 |
| 旅行随行 | 标准套餐 | 人日 | 人数、天数、每日时长、车辆、非武装/武装申请 |
| 固定场所守卫 | 驻场方案 | 岗位/班次/月 | 岗位数、覆盖时间、服务天数 |
| 活动安保 | 定制方案 | 评估后报价 | 场地、人数规模、时间、出入口与岗位需求 |
| 武装押运 | 定制方案 | 评估后报价 | 起终点、时间、货物类别、车辆与风险信息 |
| 长期驻场安保 | 驻场方案 | 岗位/班次/月 | 岗位数、每日覆盖时间、服务周期 |
| 风险评估 | 定制方案 | 人天及交付物 | 地点数量、评估范围、报告要求 |
| 安保培训 | 定制方案 | 课程/天/人数 | 课程主题、人数、天数、地点 |

固定场所守卫（`site-guarding`）属于驻场方案，按岗位、班次和月服务期评估，不适用标准短期服务的人员小时、天数或车辆计价。第一阶段尚未实现驻场专用月度报价模型；因此该服务页面必须显示“评估后报价”并允许客户提交需求，不得生成自动总价或订金。

武装选项的含义是“提交配置申请”。页面必须显示“需审核确认”，客户付款不代表服务已获批准或已经安排。后台按国家、地区和服务单独控制是否显示该选项。

## 4. 用户角色

### 4.1 客户

无需注册。姓名必填；手机号或邮箱至少填写一项；微信和WhatsApp选填。客户通过不可猜测的随机查询链接，并再次验证手机号或邮箱，访问订单。

客户可浏览服务、配置套餐、查看预估费用、提交需求、查看转账说明、上传付款凭证、确认最终方案、查看待付金额、申请取消和查看退款状态。

### 4.2 国家负责人

坦桑尼亚负责人只处理坦桑尼亚订单，泰国负责人只处理泰国订单。可核实付款、填写最终方案、调整经授权的订单报价、安排服务、处理取消退款、维护本国收款说明和地区参数。

不能查看另一国家订单，不能修改总管理员限定的权限和全局配置。

### 4.3 总管理员

查看及管理两国全部业务；管理账号权限、服务目录、价格版本、语言内容、地区开放状态、收款账户、订金规则、取消规则和操作记录。

## 5. 客户页面结构

1. 首页：国家选择、语言选择、九类服务卡片、服务承诺和订单查询入口。
2. 服务列表：按出行、场所、活动、押运、评估和培训分类。
3. 服务详情：适用场景、包含/不包含内容、套餐比较、可调整配置、预约限制和取消规则摘要。
4. 费用测算：逐项显示人员、超时、车辆、地区附加费、税费状态、预估总价和订金。
5. 预约表单：日期、地点、联系人、行程或项目需求及必要附件。
6. 付款说明：实际结算币种、收款主体、账户信息、应付金额和凭证上传。
7. 订单查询：订单摘要、状态时间线、付款记录、最终方案、待办事项、取消及退款状态。
8. 规则页面：隐私说明、服务条款、取消退款规则和数据使用说明。正式内容由业务方审核后发布。

页面采用深蓝科技风和青绿色重点色，服务卡片强调场景、配置与价格起点。移动端优先，最小支持宽度320像素；桌面端居中扩展。暂定品牌名称可以整体替换，不写死在业务数据中。

## 6. 核心业务流程

### 6.1 标准短期服务

选择国家和服务 → 选择套餐 → 调整人数、日期、时长及车辆 → 查看预估价 → 填写联系人和需求 → 提交订单 → 查看订金及转账信息 → 上传订金凭证 → 负责人核实到账 → 负责人发送最终方案 → 客户确认方案 → 上传尾款凭证 → 负责人核实到账 → 安排服务 → 完成订单。

### 6.2 驻场服务

填写岗位、覆盖时间和服务周期 → 系统显示预算或提示评估 → 支付固定预约订金 → 负责人确认排班、月费和取消规则 → 客户确认 → 订金抵扣首期 → 补齐首期款 → 开始服务 → 后续每月提前付款。

第一阶段中，固定场所守卫必须走“提示评估 → 提交需求”的分支，不显示预算、自动总价或自动订金；待驻场月度模型和业务输入完成后，才可启用本流程中的预算与付款步骤。

### 6.3 定制服务

填写项目需求 → 显示“评估后报价”及固定预约订金 → 上传订金凭证 → 核实到账 → 负责人评估并发送方案 → 客户确认或在确认前取消 → 确认后按方案约定支付余款。

### 6.4 取消退款

- 最终方案确认前：客户取消，已收订金全额退还。
- 最终方案确认后：短期服务按后台设置的时间分档规则；驻场、押运及其他定制项目使用方案内明确规则。
- 退款由负责人线下办理，并在后台登记金额、币种、凭证、时间和操作人。
- 系统不得把“已申请退款”自动显示为“已退款”。
- 最终总价小于已收订金时，系统生成应退差额，不能静默将尾款归零后结束订单。

## 7. 订单和资金状态

### 7.1 订单主状态

草稿、待支付订金、订金凭证待核实、订金已到账/方案准备中、最终方案待确认、待支付尾款或首期余款、付款凭证待核实、已收款/待安排、服务已安排、服务进行中、已完成、已取消。

### 7.2 付款状态

每笔订金、尾款、月付款独立记录：待支付、凭证待核实、部分到账、已到账、核实失败、退款处理中、部分退款、已退款。

订单状态和付款状态分开存储，避免“上传了凭证”被误认为“已经到账”。每次状态变化记录操作人、时间、原状态、新状态和备注。

## 8. 报价模型

### 8.1 标准短期套餐

未税预估价＝人数×天数×每日售价＋人数×天数×超出基础时长×超时售价＋车辆数×天数×车辆售价＋已确认附加费。

含税试算总价＝未税预估价×（1＋适用税率）。标准订金为含税试算总价的一定比例。

### 8.2 驻场成本模型

覆盖总工时＝岗位数×每日覆盖小时×月服务天数。

计划人员数＝向上取整（覆盖总工时÷每人月有效工时×排班缓冲系数）。

月总成本＝计划人员数×每人月薪成本×（1＋用工附加比例）＋管理、设备、交通、保险及其他实际成本。

未税建议价＝月总成本÷（1－目标毛利率）。最终人数和排班由当地负责人复核。

本模型适用于固定场所守卫和长期驻场安保。第一阶段尚未把它实现为面向客户的自动报价：固定场所守卫（`site-guarding`）和长期驻场安保都必须返回评估后报价，不能退回使用第8.1节的短期人员、天数或车辆价格。

### 8.3 定制项目

按评估、执行、报告、车辆、差旅、场地、设备、保险及教材等实际成本汇总，再按目标毛利率形成内部建议价。缺失成本必须显示为“待填写”，不能默认为免费。

### 8.4 价格版本

每条价格参数保存国家、地区、服务、计价单位、金额、币种、含税状态、来源、更新人、生效时间和失效时间。订单提交时保存价格快照；后续调价不影响既有订单。

公开市场价格只作为内部对照，不能自动成为正式售价。

## 9. 币种与收款

内部预算可统一换算为美元。对客展示币种、合同币种和付款币种必须可分别配置，不能默认所有交易均以美元结算。

坦桑尼亚本地业务默认准备坦桑尼亚先令价格及付款说明；只有业务方确认适用条件后，才为具体客户类型启用外币方案。泰国的美元收款能力、税务及账户安排同样由业务方核实后配置。

每个国家可配置多个收款账户，订单只显示负责人选定并处于启用状态的账户。账户修改不覆盖历史订单中的付款说明快照。

第一阶段不接在线支付接口。客户上传凭证后始终进入人工核实状态。

## 10. 多语言内容

产品结构支持中文、英文、泰文和斯瓦希里文。服务名称、描述、套餐、包含项目、预约提示和规则均按语言独立编辑；价格、配置和库存规则共享。

未完成翻译的内容不能自动发布。后台显示四语完成状态，总管理员可以只发布审核完成的语言。正式法律及退款文字需由合适的语言人员复核。

## 11. 管理后台模块

- 订单工作台：按国家、状态、服务和日期筛选，显示当前待办。
- 报价与方案：编辑配置、费用明细、方案说明、取消条款和有效期。
- 收付款：查看凭证、登记到账、部分到账、退款和核实备注。
- 服务管理：产品、套餐、图片、可调整项、预约时间及加急规则。
- 地区与价格：国家、城市/区域、价格版本、币种及附加费。
- 内容与翻译：四语内容完成度、审核和发布。
- 收款设置：按国家配置账户和转账说明。
- 权限管理：总管理员和国家负责人账号。
- 操作记录：价格、方案、付款、退款、状态及权限变更日志。

第一阶段服务安排只记录负责人填写的人员配置摘要、集合地点、时间和联系人，不建设完整排班系统。

## 12. 数据与安全要求

- 查询链接使用高强度随机令牌，并配合手机号或邮箱验证；订单编号不能直接授权访问。
- 行程、地址、联系信息和付款凭证不得出现在公开网址参数中。
- 凭证文件仅对订单所属国家负责人和总管理员开放。
- 所有后台账号必须使用安全登录和会话过期机制；连续失败登录应暂时限制尝试。
- 敏感数据传输使用加密连接，文件采用受控访问地址。
- 关键操作记录不可由普通国家负责人删除。
- 数据保留期限和删除流程在上线前由业务方根据运营主体和适用规则确定；第一阶段开发先提供可配置期限及管理员删除流程，不预设永久保存。
- 客户提交前必须看到并同意隐私说明和服务条款版本；系统保存同意的版本及时间。

## 13. 错误和异常处理

- 参数不足时不生成虚假总价，显示“待评估”。
- 地区未配置价格时允许提交需求，但不显示零元。
- 上传凭证失败时保留订单，并允许重新上传。
- 同一付款凭证重复提交时提示负责人核实，不自动重复记账。
- 负责人修改客户已确认方案时，原确认失效，客户必须重新确认新版本。
- 服务无法承接时，负责人可提出替代方案；客户不接受则按方案确认前规则退款。
- 汇率或价格过期时提醒管理员更新，但不改写历史订单。

## 14. 验收标准

1. 九类服务均能在后台独立上下架，并按国家控制可用范围。
2. 标准套餐调整人数、时长和车辆后，费用明细及订金同步变化。
3. 定制服务没有完整价格时显示“评估后报价”，不显示零元或伪造总价。
4. 未注册客户能提交订单；缺少姓名或同时缺少手机号和邮箱时不能提交。
5. 上传付款凭证后状态为“待核实”，只有负责人可以标记到账。
6. 最终方案显示总价、已收订金、待付余款和适用取消条款；客户明确勾选后才能确认。
7. 方案发生实质修改后，必须重新获得客户确认。
8. 国家负责人无法访问另一国家订单，总管理员可访问全部。
9. 后台调价不影响历史订单价格快照。
10. 四语内容未审核时不能误标为已发布。
11. 320像素宽手机页面无关键内容遮挡，表单可用键盘完成操作。
12. 客户无法仅凭订单号访问订单详情。

## 15. 实施顺序建议

第一批：客户服务浏览、报价配置、预约表单、订单查询、管理后台产品及订单基础功能。

第二批：付款凭证、人工核款、最终方案确认、退款记录、四语内容管理和权限隔离。

第三批：操作审计、数据保留设置、移动端全面测试、内容审核、部署及上线检查。

独立APP、在线支付和完整人员排班在网页业务得到验证后单独立项。

## 16. 已确定决策与上线前业务输入

已经确定：自营团队、两国负责人分开处理、客户免注册、混合订金、人工转账、短期开始前付清、长期按月预付、方案确认前订金全退、套餐加可调整配置、四种语言框架。

以下属于上线内容录入，不改变本规格的系统结构：正式品牌名称及Logo、各项真实成本和售价、税率、收款账户、每项服务预约提前量、加急费、方案确认后的退款分档、各地区武装服务开放条件、隐私和服务条款正文、四语正式翻译、真实产品图片。

这些内容可在后台配置完成后再发布；任何未审核内容保持未发布状态。
